# UC-08 Сократить ссылку

**Основной актор:** Создатель (пользователь или партнёр)
**Другие акторы:** Внешняя система (от имени создателя, по его API-ключу)
**Сервис:** link-service (аутентификация и лимит запросов — gateway)
**Требования:** F-3.1 – F-3.21; связи: F-1.5, F-8.3, F-10.2, F-10.3, F-10.17, F-12.2, F-12.3, F-12.6, F-12.7, F-12.9
**Уровень:** цель пользователя

**Цель:** получить короткую ссылку на длинный URL.

## Предусловия

- Создатель зарегистрирован и подтвердил email (F-1.5).
- Создание ссылок для аккаунта не приостановлено (F-10.17).

## Постусловия

**Успех:**

- создана новая ссылка: принадлежит создателю, действует, статус безопасности «не проверена», проверка запущена;
- или возвращена уже существующая ссылка создателя (4d, 5a);
- клиент получил короткую ссылку, и по ней сразу можно перейти.

**Неудача:** ничего не создано, суточный лимит не потрачен (F-12.9).

## Основной сценарий

1. Клиент отправляет длинный URL и, по желанию, свой код, заголовок, теги и срок жизни (F-3.3).
2. Система аутентифицирует клиента по токену и определяет создателя.
3. Система проверяет URL: схема `http`/`https`, есть домен, длина до 2048, не `sho.rt` и не его поддомены (F-3.9,
   F-3.10).
4. Система проверяет необязательные поля: свой код, заголовок, теги, срок жизни (F-3.3, F-3.14, F-3.17, F-3.19).
   Если передан свой код — см. 4b–4e.
5. Система ищет у создателя действующую ссылку на тот же URL, созданную без своего кода (F-3.5, F-3.8), и не находит её.
6. Система проверяет суточный лимит создания ссылок (F-12.2).
7. Система генерирует код (F-3.13).
8. Система сохраняет ссылку: код, URL, владелец, заголовок, теги, срок жизни, статус «действует», статус безопасности
   «не проверена», время создания (F-10.2).
9. Система запускает проверку безопасности. Пока она идёт, ссылка работает как безопасная (F-10.2, F-10.3).
10. Система возвращает `201`: короткую ссылку `https://sho.rt/{код}`, код и все сохранённые поля (F-3.4).

## Альтернативные сценарии

**Аутентификация и доступ**

- **2a.** Запрос пришёл от внешней системы → аутентификация по API-ключу, создатель — владелец ключа (F-8.3). Далее шаг
  3.
- **2b.** Токен или ключ отсутствует, невалиден или отозван → `401`. Конец.
- **2c.** Email создателя не подтверждён → `403` (F-1.5). Конец.
- **2d.** У аккаунта есть заблокированная ссылка, создание приостановлено → `403` (F-10.17). Конец.
- **2e.** Превышен лимит запросов к API → `429` с временем повтора (F-12.3, F-12.7). Конец.

**Проверка URL и полей**

- **3a.** URL некорректный → `400` с описанием причины (F-3.12). Конец.
- **3b.** URL ведёт на `sho.rt` или его поддомен → `400` (F-3.10). Конец.
- **4a.** Некорректное поле → `400` со списком ошибок. Конец. Варианты:
    - заголовок длиннее 200 символов;
    - больше 10 тегов или тег длиннее 50 символов;
    - срок жизни раньше чем через 5 минут.

**Свой код** (клиент передал код в шаге 1)

- **4b.** Код не проходит формат (3–30 символов: латиница, цифры, `-`, `_`) или совпадает со служебным путём без учёта
  регистра → `400` (F-3.14, F-3.17). Конец.
- **4c.** Код свободен → шаг 5 пропускается (F-3.6), затем шаг 6, шаг 7 пропускается, ссылка сохраняется со своим кодом.
- **4d.** Код занят действующей ссылкой этого же создателя на тот же URL → `200` с этой ссылкой (F-3.16). Конец.
- **4e.** Код занят, и это не случай 4d (другой создатель, другой URL, ссылка архивная, удалена или истекла) → `409` (
  F-3.16, F-3.21). Конец.

**Повторное сокращение**

- **5a.** Найдена действующая ссылка без своего кода на тот же URL → `200` с ней. Заголовок, теги и срок жизни из
  запроса не применяются (F-3.5). Конец.

**Лимит**

- **6a.** Суточный лимит исчерпан → `429` с временем, когда можно повторить. Лимит не тратится (F-12.7, F-12.9). Конец.

**Сохранение**

- **7a.** Сгенерированный код уже занят → система генерирует новый, клиент этого не видит.
- **8a.** Свой код заняли параллельно между проверкой и сохранением → `409`, квота возвращается. Срабатывает
  уникальность кода в БД.

## Бизнес-правила

- **BR-1.** Сгенерированный код: 7 символов, строчная латиница и цифры без `0`, `o`, `1`, `l`, `i` (F-3.13).
- **BR-2.** Свой код: 3–30 символов, латиница, цифры, `-`, `_` (F-3.14).
- **BR-3.** Регистр в коде важен; служебные пути запрещены без учёта регистра (F-3.15, F-3.17).
- **BR-4.** Код ссылки после создания не меняется (F-3.18).
- **BR-5.** Ссылки разных создателей независимы (F-3.7).
- **BR-6.** Истёкшие и удалённые ссылки при повторном сокращении не учитываются (F-3.8).
- **BR-7.** Без срока жизни ссылка бессрочная (F-3.20).
- **BR-8.** Сайт и API тратят один и тот же лимит (F-12.6).
- **BR-9.** Код, однажды занятый, никогда не освобождается (F-3.21).

## Вход / выход

**Вход:**

- `url` — обязательно;
- `code` — по желанию;
- `title` — по желанию;
- `tags` — по желанию;
- `expiresAt` — по желанию.

**Выход:**

- `shortUrl`, `code`, `url`, `title`, `tags`, `expiresAt`, `status`, `safetyStatus`, `createdAt`;
- `201` — ссылка создана, `200` — возвращена существующая.

## Открытые вопросы

- Алгоритм генерации кода (BR-1) не выбран.
- Два одинаковых запроса без своего кода, пришедшие одновременно, могут создать две ссылки на один URL. Принять это или
  защищаться уникальным индексом?
- Механизм запуска проверки безопасности (шаг 9) пока не выбран: события отложены.
