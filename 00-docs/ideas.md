# Черновик: идеи и отложенные решения

## Безопасность: быстрая проверка при создании

**Проблема.** По F-10.2 ссылка работает как безопасная, пока идёт проверка. Опасную ссылку можно разослать сразу после `201`, и первые переходы пройдут на фишинг.

**Идея.** Разделить проверку на две части.

1. **Быстрая, синхронная, до сохранения ссылки** — миллисекунды, без сетевых вызовов:
    - свой чёрный список доменов (F-10.9);
    - локальная копия базы опасных адресов (Google Safe Browsing Update API, хэши в Redis или в памяти);
    - дешёвые признаки: IP вместо домена, подмена букв.

   Опасно → `400`, ссылка не создаётся.
2. **Медленная, асинхронная, после создания** — как сейчас в F-10.2:
    - редиректы до конечного адреса;
    - возраст домена;
    - чужой бренд в домене.

**Если принять:** поменять F-10.2 и добавить в UC-08 шаг «быстрая проверка» с альтернативой «URL опасен → 400».

**Статус:** отложено.
