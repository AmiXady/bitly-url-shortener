# Функциональные возможности

> Что умеет система — коротко и без деталей. Это верхний уровень требований
> по подходу Head First OOA&D: каждая возможность дальше раскрывается в набор
> конкретных требований.
>
> **Каждая возможность детализирована в папке [`features/`](features)** — отдельный файл
> на каждую, номер файла совпадает с номером возможности (`04-…md` → F-4).
>
> Функциональность — урезанная часть [Bitly](https://bitly.com).

## Акторы

| Актор            | Кто это                                                                     |
|------------------|-----------------------------------------------------------------------------|
| **Пользователь** | Зарегистрирован. Создаёт ссылки по одной через сайт                         |
| **Партнёр**      | Зарегистрирован. Магазины и сервисы рассылок, создают ссылки массово по API |
| **Посетитель**   | Кто угодно в интернете, переходит по ссылкам. Без регистрации               |
| **Робот**        | Мессенджеры, соцсети, почтовые антивирусы. Заходят по ссылкам автоматически |

**Создатель** — пользователь или партнёр, который создал ссылку.

## F-1. Регистрация и вход

Человек заводит аккаунт и входит в него. Без аккаунта создавать ссылки нельзя —
так у каждой ссылки есть владелец.

## F-2. Доступ к API по ключу

Создатель выпускает ключи для работы через REST API и отзывает их.
Один ключ открывает все ссылки аккаунта — партнёру не нужно хранить
отдельный токен на каждую из тысяч ссылок.

## F-3. Сокращение ссылки

Создатель отправляет длинный URL и получает короткую ссылку. Можно задать свой код,
заголовок, теги и срок жизни. Система проверяет, что URL корректный.

## F-4. Массовое сокращение

Создатель загружает CSV-файл с тысячами длинных ссылок — например, персональные ссылки
для рассылки — и скачивает файл-результат с короткими. Ошибка в одной строке не мешает создать остальные.

## F-5. Просмотр своих ссылок

Создатель видит все свои ссылки, ищет и фильтрует их, открывает одну ссылку целиком.
Работает одинаково быстро и для 10 ссылок, и для миллионов у крупного партнёра.

## F-6. Изменение ссылки

Создатель меняет заголовок, теги, срок жизни и адрес назначения — например,
чтобы исправить ошибку после рассылки. Сама короткая ссылка при этом не меняется.

## F-7. Архивирование и удаление

Создатель убирает ссылку из списка, не ломая её (архив), или отключает её совсем (удаление).

## F-8. Изоляция данных владельца

Создатель видит и меняет только свои ссылки и их статистику. Чужие ссылки для него
неотличимы от несуществующих.

## F-9. Переход по ссылке

Посетитель открывает короткую ссылку и попадает на оригинальный адрес.
Если ссылки нет, она истекла, удалена или опасна — видит понятную страницу вместо редиректа.

## F-10. Проверка ссылок на безопасность

Система проверяет адреса на фишинг и вредоносное ПО, предупреждает посетителей
о подозрительных ссылках и блокирует опасные. Любой может пожаловаться на ссылку.

## F-11. Статистика переходов

Создатель видит, сколько людей перешли по его ссылке и как переходы распределены по времени.
Переходы роботов не считаются.

## F-12. Лимиты использования

Система ограничивает, сколько ссылок и запросов может сделать аккаунт за период.
Это защищает честных пользователей от тех, кто перегружает сервис или рассылает спам.
